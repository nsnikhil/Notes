### Source Code Crash Analysis

The following potential runtime crash points were identified by scanning the actual source code. These inform the implementing agent but do not represent gaps in the requirements — REQ-003 through REQ-005 already mandate finding and fixing all such issues:

1. **`<fragment>` tag in `activity_main.xml` (line 45)** — Uses the deprecated `<fragment>` XML tag for `NavHostFragment`. With Navigation 2.8.5, this is a known crash source. The recommended fix is replacing `<fragment>` with `<androidx.fragment.app.FragmentContainerView>`. This is the most likely cause of the immediate launch crash.

2. **`ContextModule` initialized at field declaration time in `MyApplication.kt` (line 50)** — `private var contextModule: ContextModule = ContextModule(this)` passes `this` before `Application.onCreate()` runs. While this worked historically, it's a fragile pattern that can cause issues with newer Android framework versions. The implementing agent should verify this doesn't cause a crash with compileSdk 35 / targetSdk 34.

3. **Missing `google-services.json`** — `FirebaseApp.initializeApp(this)` is called in `MyApplication.onCreate()`, and `apply plugin: 'com.google.gms.google-services'` is in `build.gradle`, but no `google-services.json` file exists in the project. This will crash at runtime when Firebase tries to initialize. The build may succeed because the google-services plugin generates a placeholder, but runtime initialization will fail.

4. **`NetworkComponent` is `abstract class` instead of `interface`** — All other Dagger components are interfaces, but `NetworkComponent` is an abstract class. Dagger 2.53.1 may handle this differently than older versions. The implementing agent should verify this doesn't cause a Dagger code generation issue.

5. **`NotesDatabase` version 1 with no migration strategy** — Room 2.6.1 is stricter about schema validation. If the database schema generated by Room 2.6.1 differs from the version 1 schema created by Room 2.0.0 (e.g., due to `@Serializable` annotation on entities or different nullability handling), Room will throw an `IllegalStateException` at runtime. No `fallbackToDestructiveMigration()` is configured.

6. **`NoteEntity` has both `@Serializable` (kotlinx) and `java.io.Serializable`** — The `@Serializable` annotation may cause Room's annotation processor to generate different schema metadata than before, potentially triggering a schema mismatch even though the database version hasn't changed.

7. **Deprecated `setTargetFragment` in `PrefFragment.kt` (line 109)** — `dialog.setTargetFragment(this, 1954)` is deprecated and may throw `IllegalStateException` with Fragment 1.8.5 if the fragment is not in the same FragmentManager. This won't crash on launch but will crash when navigating to Settings and tapping "Change Password".

8. **`findNavController(R.id.mainNavHost)` in `MainActivity`** — With `<fragment>` tag, `findNavController` may fail because the fragment hasn't been added to the FragmentManager yet during `onCreate`. Replacing `<fragment>` with `FragmentContainerView` also requires changing `findNavController(R.id.mainNavHost)` to use `supportFragmentManager.findFragmentById(R.id.mainNavHost)` to get the NavController, since `FragmentContainerView` doesn't support `findNavController` by view ID the same way.
